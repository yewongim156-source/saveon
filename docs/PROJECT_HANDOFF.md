# Save:on 개발 현황 및 이어서 할 작업

## 이어서 진행한 작업 (2026-11-17)

- `verified_summary.py`의 전체 검증 상태 판정을 보수적으로 수정했다. 검증 대상 주장마다 같은 내용의 SUPPORTED 결과와 출처 URL이 있어야 VERIFIED이며, 일부만 확인된 경우 PARTIALLY_VERIFIED다. 이 상태는 검증 대상으로 추출된 주장에 관한 것이고 전체 요약의 모든 내용이 사실이라는 뜻은 아니다. URL의 존재만으로 출처 적합성이 보장되지는 않는다.
- 관련 테스트 2개를 추가했고 AI 단위 테스트 21개가 통과했다. STT/OCR ID의 의미상 적합성은 여전히 자동 확인하지 않는다.
- 로컬 상태 확인에서 AI 및 개발자 API는 응답했지만 Spring API 8080은 응답하지 않았다. 최신 코드의 전체 E2E는 미실행이다. 기존 실행 중인 AI 프로세스가 수정된 코드를 반영했는지도 확인되지 않았다.

## 작업 효율 원칙

- 작업 시작 때 관련 Git 상태와 필요한 파일을 묶어 확인하고, 같은 상태를 반복 조회하지 않는다.
- 로그는 관련 부분과 오류 위주로 제한하고, 성공한 테스트를 이유 없이 재실행하지 않는다.
- 실험은 소수의 대표 영상과 명확한 질문으로 시작하며, API 호출 횟수와 무료 할당량을 고려한다. 실패 시 원인을 먼저 확인한다.
- 장시간 작업은 한 번에 장시간 대기하지 않고 의미 있는 변화가 있을 때만 진행 상황을 알린다. 이러한 원칙은 검증을 생략하라는 뜻이 아니다.

작성일: 2026-11-17. 이 문서는 현재 로컬 체크아웃과 이전 실행 기록을 기준으로 한 인수인계다. 다른 개발자의 원격 브랜치는 마지막으로 2026-11-08에 fetch한 상태이므로, 통합 전 다시 확인한다.

## 현재 구현과 검증 수준

- YouTube URL 분석, Instagram Reel 분석 코드, 영상 업로드, 비동기 처리, PostgreSQL 저장, Gemini 구조화와 임베딩/pgvector 검색이 현재 브랜치에 있다. Instagram의 실제 접근 성공률과 플랫폼 정책 준수는 별도 검토가 필요하다.
- 초기 YouTube E2E는 성공한 바 있다. 이후 수정된 최신 근거 연결 코드는 전체 E2E 확인 전이다. 마지막 시도는 Spring이 준비되기 전 요청해 연결이 거부됐다. 재시작 후 `/health`와 Spring `8080` 응답을 확인하고 재시험한다.
- OCR은 기본 2초 간격, 최대 60프레임으로 변경했고, STT 구간과 OCR 문구에 ID와 시간 정보를 생성한다. 실제 프레임 간격은 길이와 상한 때문에 더 커질 수 있다. 중복 OCR은 첫 등장 시각만 보관한다.
- Gemini가 대상명·상세·단계에 STT/OCR ID를 연결하도록 수정했다. 존재하지 않는 ID만 제시한 항목은 제외하고, 결과는 영상에서 유래한 미검증 정보로 표시한다. **ID가 존재하는 것만으로 의미상 근거 일치나 사실 검증이 보장되지는 않는다.**
- JSON 출력 상한을 4096으로 변경하고 구조화 실패 시 원시 OCR을 정상 요약처럼 보여주지 않도록 했다. 검색 실패 시 검증 요약으로 원본 내용을 덮어쓰지 않는다.
- 구조화된 targets/steps와 증거는 백엔드 응답에 담기지만 현재 브랜치의 모바일 상세 화면에서 전용 카드/근거 뷰로 구현되지는 않았다. 다른 개발자가 사용자 화면 및 행동 카드를 담당할 가능성이 있으므로 먼저 협의한다.
- 화장품·복근 영상의 기존 추출 데이터로 최신 근거 연결을 Gemini에 재실행해 각각 5개 대상을 확인했다. 검색은 429 실패. 전체 영상·정확도에 대한 일반화나 외부 사실 검증 성공으로 볼 수 없다.
- AI 단위 테스트 19개가 2026-11-11에 통과했으나 이후 코드를 다시 실행해 현재 상태를 검증해야 한다.

## 미완료 및 권장 순서

1. 로컬 변경을 검토하고 단위 테스트를 다시 실행한다. 각 target/step의 ID가 실제 해당 문장을 뒷받침하는지 확인하는 테스트를 추가한다. 현재는 ID 존재만 검사하므로 잘못된 ID 연결이나 STT/OCR 오인식을 막지 못한다.
2. 서비스 준비 상태를 확인하고 화장품·복근 등으로 최신 코드 E2E를 재실행한다. DB 저장과 기존 모바일 응답 호환, fallback·검증 실패 문구를 확인한다.
3. 건강·제품 관련 내용의 노출을 점검한다. 영상 내 주장을 영상의 주장으로 표시하는 것과 외부 사실을 검증하는 것은 다르며, 검색 실패를 ‘거짓’이나 ‘검증됨’으로 바꾸지 않는다. 부분 검증 결과가 전체 항목을 인증하는 것처럼 보이지 않도록 한다.
4. 무료 외부 검색 후보의 공식 조건을 다시 확인하고 선정한다. Brave Search는 월 무료 크레딧이 있으나 카드 등록이 필요한 조건을 확인한 바 있다. Wikimedia 검색은 백과사전 범위, PubMed는 의생명 문헌 범위에 한정된다. 검색 결과 자체가 검증은 아니며 출처가 주장·제품과 일치하는지 추가 판단해야 한다. Gemini 3 Search Grounding은 이전 Free tier 호출에서 429였으며, 요금표·계정별 지원을 확인한다. 결제 전환 금지.
5. 네가 제공한 10개 영상의 전체 내용을 사람이 검토해 대상별 정보·순서·외부 근거 정답을 작성한다. 파일럿에 제품별 속성과 순서 정답이 충분히 채워지지 않았다. 사실검증 정답은 독립적인 출처와 확인일을 기록한다.
6. 근거 적합성, 대상 누락·연결 오류, 단계 순서, 검증 오류·출처 적합성, 처리 시간 및 호출량을 측정하는 평가 러너를 만든다. OCR 6프레임·2초 간격·화면 변화 기반을 같은 환경에서 반복 비교한다.
7. Gemini 응답의 실제 사용량 메타데이터와 호출 횟수를 수집한다. 현재 개발자 API에 token/cost 필드는 있지만 실제 Gemini usage 연결 여부가 확인되지 않아 0을 실제 사용량으로 해석하면 안 된다.
8. 다른 개발자 브랜치 최신 내용을 확인하고 안전하게 통합한 후 사용자 화면·행동 카드 및 전체 E2E를 함께 검증한다.
